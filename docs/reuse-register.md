# 复用台账（reuse-register）

> **为什么单独建这份台账**：设计文档 §7 的复用矩阵回答"当初为什么选这两个参考项目"，
> 但它不回答"具体哪一条借鉴落到哪个文件、现在是什么状态"。缺了后者，复用理由会随记忆蒸发，
> 最后变成"当初好像参考过"。本台账逐条登记：借鉴什么、落在哪、做到没有、什么条件下复核。
>
> **维护纪律**：只增不删；状态变更追加一行并注明日期（原行保留，便于追溯判断演变）。
> 与 `docs/SPEC-*` 的 §x.7 证据链互补——那边证明"功能做完了"，这边证明"设计有出处"。

## 1. 复用判定顺序（用户 2026-11-16 指令，落为硬约束）

选定任何实现方式前，按序尝试，**前一档能解决就不进入下一档**：

| 序 | 手段 | 判定标准 | 反面 |
|---|---|---|---|
| 1 | 复用本仓已有方案与架构 | 已有接口/模式能扩展着用（开闭原则） | 另起一套平行抽象 |
| 2 | 语言机制直接达成 | C++23 标准库/语言特性够用 | 手写替代标准库能力 |
| 3 | 评估后引入三方库 | 先调研、跑通最小验证、比对许可与体积 | 凭"听说好用"引入，或无验证直接上 |
| 4 | 自造 | 前三档均不可行，且写清为何不可行 | 一上手就造轮子 |

引入三方库必须同步：`vcpkg.json` 锁版 + `implementation-notes.md` 记选型理由 + 本台账登记。
技术栈锁定（asio / protobuf / spdlog / gtest / unordered_dense）之外新增依赖属高风险，
须与用户核对——这条与 CLAUDE.md §4/§13 同源，避免"悄悄换技术栈"。

## 3. Mooncake（KVCache 分离式存储，Apache-2.0）

**定位**：只借**架构原则与接口语义**，不引入其数据模型（不可变对象、best-effort 副本、
租约过期读失败语义都与本项目的强一致可变 KV 相斥）。代码级复用限于工具层，且需保留
Apache-2.0 许可声明与 NOTICE。

| # | 借鉴内容 | 类型 | 落地位置 | 状态 |
|---|---|---|---|---|
| M-1 | 控制面 / 数据面分离：调度器只动元数据，数据不经它转发 | 架构原则 | `docs/SPEC-3` §3.2（Scheduler 仅元数据） | 已落设计，M4 验证 |
| M-2 | 大数据走独立流式通道，不阻塞控制通道 | 架构原则 | `docs/SPEC-2` §2.3.1 `Transport::open_snapshot_stream` | 已落设计，M2 验证 |
| M-3 | 传输抽象四层语义：请求 / 批量 / 提交 / 状态查询 | 接口形态 | `docs/SPEC-2` §2.3.1（首版 asio TCP 实现，留多后端插槽） | 已落设计，M2 验证 |
| M-4 | 两阶段写入防脏读（先占位、再结束） | 机制参考 | 与 Percolator prewrite/commit 同形，见 `docs/SPEC-4` §4.4 | 已落设计，M5 验证 |

**明确不借**：GPU/NCCL/RDMA 相关条件编译（本项目零特殊硬件依赖）、对象不可变语义、
best-effort 副本、租约过期读失败。理由见设计文档 §7 与 §3.7 非目标。

## 4. 复核触发条件（什么时候必须回来重看这张表）

- **换里程碑时**：M2 / M4 / M5 开工前逐条核对本表对应行，把"已落设计"改判为"已验证"或"放弃并记原因"。
- **性能不达标时**：若 PERF-0x 未达 S0，先回看 X-3/X-4 是否有回潮（历史教训最容易复发）。
- **准备搬代码时**：先确认许可证并在此登记，再动；未登记不得复制任何第三方源码。
- **新增三方库时**：按 §1 顺序提供评估与最小验证证据，未走流程的依赖一律退回。

## 4.1 [2026-11-16] M4 ④b 复核记录（按 §4"换里程碑/子层时"触发）

本层（Learner 追平 + 两节点移除边界）按复用判定顺序落地，逐条核对：
- **档 1 复用本仓**：追平计时复用 M3 已有的 `now_ticks_` 单调计数口径（租约同源），未新造时钟；
  错误复用 `InvalidArgument`（KvError 6 变体之一），未扩错误契约；测试复用 `Cluster`/`add_node`/`ConfChange`
  与 `leaner` 复制链路；追平判定与 M3 租约判定同构（tick 度量、不读墙钟）。
- **档 2 语言机制**：learner 差判定用 `std::map::find` + 三元表达式；追平起点用 `try_emplace`；
  阈值 `constexpr` 常量；清理残项用 map 迭代 erase——全为标准库，零新依赖。
- **档 3/4 未触发**：本层无需引入三方库，也无需自造数据结构；proto 零改动。
- **KVstorageBaseRaft-cpp 反模式复核**：其"读走共识/心跳带全量日志"在 M2 已立 PERF-03/08 防回归；
  本层改 broadcast_append 时仍坚持"心跳只带元数据"（未借其坏做法）。X-1~X-6 无回潮。
- **Mooncake 架构原则复核**：本层"控制面（AddVoter 门槛判定）与数据面（日志复制）分离"延续 M-1，
  门槛判定在状态机、复制走既有 send_append，未让元数据判定阻塞数据通道。

结论：④b 全程停在档 1–2，无需进入引库/自造档；复用判定顺序得到遵守。

## 5. 与对齐检查的关系

`align` 阶段（`tools/ci/check_align.py`）只校验可判定项（契约集合、命令引用、违禁模式），
**不校验本表**——"这条借鉴是否真的落地了"属于语义判断，归人在里程碑复核时判定。
本表的作用是让人在复核时有据可查，而不是让机器替人下结论。
